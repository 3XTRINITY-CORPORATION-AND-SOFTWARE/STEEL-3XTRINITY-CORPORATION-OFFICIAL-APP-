# Mutation checks and RÄSTIK v2 attack report (closed loop guards)

## 1. Mutation-testing harness

Code: `factory/mutation/engine.ts` (engine), `factory/mutation/mutants.ts` (catalog), `factory/mutation/run.ts` (CLI). No dependencies.

Run (Node 22, repo root; about 15-25 minutes for the whole catalog on a loaded 8-core box, 4 parallel workers):

```
node --experimental-strip-types factory/mutation/run.ts --concurrency 4 --json mutation.json --md mutation.md
node --experimental-strip-types factory/mutation/run.ts --only G01,T05      # a subset
```

How it works (deterministic: hand-written exact edits, no randomness, results ordered like the catalog):

1. Every mutant is an exact text edit of ONE source file (`find` must occur exactly once; a stale or ambiguous edit is a harness error, never a silent "survived").
2. The project (cerberus, kratt, rastik, factory, package.json, .nvmrc, .devcontainer, .github) is copied to a private temp directory and committed to a throw-away git repo (twice, so `HEAD~1` exists), because TÖEPÄRA recomputes from git. The mutant is applied to the copy before the second commit. The working tree under test is never modified.
3. `node --experimental-strip-types --test factory/tests/*.test.ts` runs in the copy (`mutation.test.ts`, the harness's own tests, is left out and also skips itself inside mutant runs via `FACTORY_MUTATION_CHILD=1`; the kill tests in `mutation-kills.test.ts` are included).
4. The baseline (no mutant) must be green first, otherwise nothing is reported as killed.
5. Outcomes: KILLED (tests fail), TIMEOUT (counted as killed, listed separately; 0 occurred), SURVIVED, INVALID (mutant does not parse/load, or the runner failed without a failing test: a harness error, NOT a kill; the run exits non-zero). A test FILE that fails as a whole because of a syntax/import error is INVALID, not killed.
6. Score = (killed + timeout) / total over ALL mutants. Equivalent mutants are NOT removed from the denominator; they can only carry a written justification (`EQUIVALENT` in `mutants.ts`). Exit code 0 only if the baseline is green, nothing is INVALID, and every survivor is annotated equivalent.

Never weakened: the harness only edits a throw-away copy; no gate in the repository was changed, skipped or made `continue-on-error`.

## 3. RÄSTIK v2 attack battery

`factory/rastik-attacks.ts`. Every case states the hypothesis "this mutated receipt / sequence / declaration gets ADMITted (or passes)". A bypass is re-run in a fresh session: reproduced => CONFIRMED finding carrying RISK (`hypothesis`), REPRODUCTION, AFFECTED COMPONENT (`target`), SMALLEST FIX (`proposed_smallest_fix`) and a REGRESSION TEST (`regression_test`, a runnable `test(...)` that fails today for open defects). A control receipt must be admitted first, and a test asserts that no case is a no-op mutation.

Default battery (run by the closed loop): 8 receipt classes, 100+ cases, all REPELLED by the real verifier:
malformed input (2 MB evidence, 1 MB task id, 10 kB scope path, 100 kB objective, 10,000-deep nesting, wrong types), prototype pollution (own `__proto__`, `constructor`, inherited prototype; asserts `Object.prototype` stays clean), Unicode confusables in task ids (Cyrillic, Greek, fullwidth, zero-width, RTL override, trailing newline, uppercase), path traversal in scope (12 variants, appended to receipt AND envelope), replay (same receipt twice, key-reordered, other task, other scope), evidence substitution (hashes / names / bytes swapped between artifacts, other task's evidence, other action, a foreign real file's real digest, dropped artifact, duplicate artifact, plus a real second genuine receipt's evidence), trust bypass (envelope that stops forbidding merge/deploy, allows merge, factory/agent mismatch, KRATT certifying KRATT with forged evidence, producer-set verification states), self-consistent forged failed / zero-check results claiming success.

Final-receipt (CERBERUS output) battery, `runFinalReceiptAttacks`: missing / null CERBERUS decision, flipped final decision, removed TÖEPÄRA result, KRATT receipt claiming VERIFIED, real_goliath claim (all flagged by `selfCheckFinalReceipt`; a deleted decision is rejected only by an uncaught TypeError, see hardening notes).

STACKED_CONFIG_COLLISION battery, `runConfigCollisionAttacks` (17 cases, injectable `configCollisionViolations`; duplicate-key-aware JSON reader `jsonDuplicateKeys`): 1, 2 and 3 stacked `test` keys (identical, and a later key that drops tests), duplicate `lint` key, duplicate `scripts` / `engines` blocks, merge-conflict markers in package.json and in a workflow, trailing-comma JSON, deleted / empty `test`, `test` ending in `|| true` or `; true`, a registered test silently dropped from the script, a new test file named nowhere, `continue-on-error: true` and `run: ... || true` in a workflow. Registration counts a test file as registered when the `test` script names it or a registered file side-effect-imports it.

Caller-supplied PASS / VERIFIED / ADMIT (default battery): a receipt carrying its own `decision: ADMIT`, `verdict: VERIFIED`, `status: PASS`, `result.status: PASS`, `evidence.verdict: PASS`, `verification_state: ADMIT` is REPELLED (closed key sets / enums), as are the existing `self-verified-by-kratt`, `state-trusted`, `kratt-self-certifies-*` cases. Not speculated: there is no lease between CERBERUS's ADMIT and the later merge; freshness is re-checked per call only.

Runtime-drift battery, `runRuntimeDriftAttacks` (21 bounded cases): `.nvmrc` other major / lts alias / empty / missing / two lines / trailing text; `engines.node` open range / caret union / other major / missing; devcontainer other major / `lts`; CI `setup-node` other major / `lts/*` / `latest` / `node` / a SECOND job on another major / no pin; the RUNNING interpreter older / newer / unreadable. `runtimeDriftViolations` rejects all 21; a re-implementation of what `scripts/node-pin.test.mjs` checks (first CI match only, no running-interpreter check) is attacked successfully by the second-job and running-interpreter cases (tested).
